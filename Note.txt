->what python actually does 
Suppose your database contains these fake accounts
Username: alice, bob
password: stored password hash, same

- when alice tries to log in the process looks like this:
     ->HTML form : Alice submits her credentials
     |
     ->Flask + python : Recieves the submitted data and runs the login logic.
     |
     ->SQLite database : Provides the account needed for verification.
     |
     ->Flask decides the result : Creates an authenticated session or rejects the login.

5. The simplest way to remember it
Component	Main responsibility
HTML:	        Structure of the webpage
CSS:	        Appearance of the webpage
JavaScript:	    Browser-side behavior
Python: 	    Application logic
Flask:  	    Routes requests to Python functions and returns responses
SQLite: 	    Stores and retrieves persistent data
These components work together; none of them replaces all the others.

-> You understand several important concepts now:
Flask : receives the login form.
SQLite : stores and retrieves user records.
Password hashing : stores a derived hash instead of the original password.
salt : makes password hashes unique, even when users choose the same password.
parameterized SQL: helps prevent SQL injection in your database query.
